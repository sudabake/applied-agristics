# Alpha.17 代码审阅与修复

审阅日期：2026-10-23。基线：Alpha.16（43077d4）。覆盖注册、种植与耗电、库存事务、种子租用、结构归属／卸载、拆卸、NBT、消息处理、培养、注魔、生物兑换、JEI、客户端、资源工具和构建。先在隔离副本复现，再修改运行代码；没有把旧测试通过当作审阅结论。

## 已复现并修复

### P2：有名称／组件的种子没有扣除重种消耗

`logic/Harvests.java` 的 `reserveSeed` 只匹配完全相同的组件。原生方块掉落通常是无自定义组件的种子；命名后的种子仍保留在机器里，但掉落中的基础种子不再扣一颗，相当于额外获得种子。相同的五颗基础种子输入，普通种子处理后剩四颗，改名种子处理后仍剩五颗。

修复先扣完全匹配种子；若原种子有组件且没有完全匹配项，再扣一颗同物品、无额外组件的原生种子。不扣另一种带组件的变体，不修改原种子身份。

### P2：少于八种材料的注魔配方兼容不完整

`block/MEInfusionAltar.java` 的 AE 接单要求材料列表长度恰好为八；神秘农业允许更少的基座材料。手动加工还假设余料一定为九格，但 Minecraft `CraftingInput` 会裁掉空行／列。一个中心材料加一个基座材料的合法配方，在隔离环境无法完成手动加工，也被 AE 拒绝。

修复允许零至八项基座材料；余料按裁切后的坐标映射回九个真实物理槽，八个基座要求仍保留。新增牛奶桶配方检查中心和基座的空桶原位返还。

### P2：漏斗取走订单结果后，自动输出标志残留

AE 接单将 `craftingDelivery` 置为 true。原实现只在自己的导出方法取空结果时清除；漏斗或玩家提前拿走结果会留下标志。随后手动制作的结果即使关闭自动输出，也会被导出。

修复在结果槽变空时清除订单导出标志。隔离复现使用真实 AE 处理样板、八个基座、外部物品接口和后续手动制作。

### P2：转移组件的注魔配方被提前拒绝

接单先把样板输出与静态 `getResultItem` 做完整组件比较，然后才安排材料。开启神秘农业 `transfer_components` 的配方可能从中心材料继承名称等组件，静态结果与实际结果不同，合法样板因而被拒绝。

修复预筛选只比较输出物品类型与数量；材料完整匹配后，仍使用实际 `assemble` 结果严格检查全部组件和数量。隔离样例为有名称的中心材料、八份基座材料以及继承名称的成品。

## 未作为本轮确定错误处理

- 普通／第三方原生掉落使用有界抽样再按批次缩放，稀有掉落可能成批出现；这不是逐株独立抽样。Botany Pots 回调采用独立有界处理。更改概率体验需要单独确定规则。
- 普通作物的主要产物通过一次真实收获推断；复杂随机掉落、特殊环境、额外战利品函数和未知自定义回调需要具体适配，不能保证自动识别全部 Mod。
- 生物掉落枚举不能自动涵盖所有代码事件掉落；新增输出受有限图案数量约束，历史禁用位置仍被保留。
- 消息操作检查菜单、坐标和距离，但没有专门的恶意客户端高频压测。不能据此声称完成了全面安全测试。
- 大规模多机性能、长时间多人存档、崩溃时磁盘写入一致性未完成实测。世界掉落队列的序列化守恒不等于异常断电时的跨文件事务保证。
- 一次沿用旧开发存档的最低前置测试在全部断言通过后，退出阶段停留于 Minecraft 区块卸载／CompletableFuture；已保留线程证据。使用新的可丢弃开发存档后，默认和最低组合均正常测试及退出。根因尚未确定，不能据此宣称已修复所有退服边界。
